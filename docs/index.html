The problem

Malaysian open data is silently breaking

An endpoint can return a file and still fail the people and agents relying on it. Availability alone is not evidence of trustworthy data.

Stale by default

Many official datasets are published once and never updated. Without verification, “available” looks like “fresh”.

No freshness signal

Most endpoints don’t send Last-Modified headers. You can’t tell a 2-day-old file from a 2-year-old one.

Licences unclear

Reuse rules are scattered across catalogue pages. Agents can’t cite what they can’t licence.

The mechanism

How one dataset gets its status

Probing is the mechanism; an honest status is the outcome. Every cycle follows the same inspectable path.

  1. 01

    Probe

    A 15-minute timer fetches each dataset: HTTP headers, content dates, record counts, schema shape.

  2. 02

    Measure

    Three freshness signals: Last-Modified header, content-date parse, browser extraction when needed.

  3. 03

    Classify

    One of eight honest statuses — never a blanket “healthy”. If we can’t prove freshness, we say so.

  4. 04

    Publish

    Health JSON, badge, report, RSS, and MCP tools update atomically — all machine-readable.

FAQ

Questions before you connect

Is this live right now?

Yes — 335 datasets probed every 15 minutes. See the live status above.

Does DataPulse replace data.gov.my?

No — it verifies and documents official sources. We never resell the data.

How fresh is “fresh”?

Within 1.5× the dataset’s declared cadence, verified by Last-Modified header or content-date.

Can I use it without an API key?

Yes — the MCP server is read-only and key-free.

Is it open source?

Yes — MIT, on GitHub, with a public changelog and reproducible build proof.
