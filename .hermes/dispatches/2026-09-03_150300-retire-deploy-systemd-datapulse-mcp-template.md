## Background

The MCP server runs as a **user-scope** systemd unit on the VPS. The live,
authoritative running config lives at `~/.config/systemd/user/datapulse-mcp.service`
plus four drop-in fragments. On 2026-09-03 that live config was reconciled and
tracked into the **private** dotfiles repo at `system-user/datapulse-mcp.service`
(commit 45bbf71) as a single consolidated, canonical unit. The dotfiles copy is
now the source of truth for VPS unit config (a dotfiles role).

The public datapulse-my repo still carries an **older, stripped template** at
`deploy/systemd/datapulse-mcp.service`. It is functionally identical except it
LACKS the three operational Environment fixes that the live unit originally
carried via untracked drop-ins:
- `Environment=PATH=/home/redza/.local/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin` (cosign verifier reachability -> live Sigstore verification);
- `Environment=PYTHONPATH=/home/redza/datapulse-my`;
- `Environment=DATAPULSE_USAGE_DIR=/home/redza/.local/share/datapulse-mcp/usage`.
It is a versioned-in-time snapshot, not the live truth, and installing it would
regress the running service. It must be retired so the canonical copy cannot be
mistaken for an authoritative install source.
